7a Builder · screen canvas desktop 1920×1080

The existing canvas already has the chrome it needs — back/home, save/discard/undo/redo, canvas and widget chips, a widget list, and position/size in the inspector. What it does not have is any way to know a widget is too small for its own content, which is how the gripper shipped cut. Four additions, all from the contract: a device-class switcher, a minimum-size check with a one-tap fix, the effective glass size after fit-scaling, and the reserved STOP region drawn on the canvas so nobody places a widget under it.

Minimum size

Reads WIDGET_MIN_SIZE for the kind and its current show_details. Warns, never blocks, and offers the exact resize as one action — ADR 0132.

Glass, not canvas

A 56 px button on a canvas fit-scaled to 0.80 is 45 px of real glass. The inspector shows both, and the number goes error-red below 44.

Reserved regions

STOP is drawn on the canvas as a dashed error region. An author cannot place a widget there, and can see why.

Device switcher

Tablet and desktop are separate apps, so the switcher moves between the paired app's screens rather than rescaling one canvas.

The rule that holds

Control labels wrap to two lines and the control grows. They never shrink their type and never truncate — a truncated verb on a robot control is a guess.

Never translated

Topics, frame ids, axis names and numbers. base_link is not a word, it is an identifier.

Needs a native speaker

These are my translations. Safety wording on a robot control has to be checked by someone who speaks the language and knows the arm — especially STOP and the resume hold.
